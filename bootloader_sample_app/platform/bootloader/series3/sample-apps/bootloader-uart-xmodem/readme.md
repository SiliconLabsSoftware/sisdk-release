# UART XMODEM Bootloader

Demonstrates how to perform firmware updates using XMODEM-CRC over UART, in a menu-driven standalone bootloader recommended for EmberZNet and Connect protocol stacks.

## Purpose / Scope

This sample builds a standalone first-stage bootloader for Silicon Labs Series 3 devices. It uses the EUART peripheral (routed through the board-controller VCOM), the XMODEM-CRC protocol for image transfer, and GBL image parsing with AES/SHA/ECDSA support for signed and encrypted firmware updates. GPIO activation is included, so a configured pin held at reset forces entry into the bootloader menu even when a valid application is present. It is the recommended UART bootloader to pair with EmberZNet and Silicon Labs Connect NCP applications, and can also be used as a generic standalone UART bootloader for any Series 3 application.

## Prerequisites / Setup Requirements

**Hardware**
- A Silicon Labs Series 3 development kit (radio board + mainboard, or a pro kit) supported by the Gecko Platform SDK.
- USB cable to the kit's board controller (provides debug access and the VCOM UART bridge to the host PC).

**Software**
- Simplicity Studio 5 (or later) with the Gecko Platform SDK installed.
- A serial terminal that supports XMODEM-CRC transfers (for example Tera Term on Windows, or `sx`/`lrzsz` on Linux).
- Simplicity Commander (for command-line flashing and creating signed GBL images).

## Steps to Run Demo

1. In Simplicity Studio, create a new project from the **Bootloader - NCP UART XMODEM** example for your Series 3 part.
2. Build the project and flash the generated bootloader image to the kit.
3. Build your target application separately, convert it to a GBL image (using `commander gbl create`), and keep the `.gbl` file handy.
4. Open a serial terminal on the kit's VCOM port at **115200 baud, 8-N-1, no flow control**, then reset the board. The bootloader menu is printed on the terminal.
5. Press `1` to start the XMODEM-CRC transfer, then use your terminal to send the `.gbl` file.
6. When the transfer completes successfully, press `2` to boot into the newly uploaded application.

## Troubleshooting

- **No menu printed on reset:** Verify the terminal is connected to the correct VCOM COM port at 115200 baud; confirm `SL_VCOM_ENABLE` is `1` and the AEM/VCOM switch on the mainboard is set to AEM so the board controller forwards UART.
- **XMODEM transfer fails or times out:** Use XMODEM-**CRC** (not checksum) and disable flow control in the terminal; make sure the file being sent is a valid signed/unsigned `.gbl` generated by Simplicity Commander.
- **Application does not start after upgrade:** Ensure the application is built with the matching bootloader interface and, if secure boot is enabled, that the GBL is signed with the correct key provisioned on the device.
- **Device always stays in the bootloader:** Check the GPIO activation pin — if it is asserted at reset (for example pulled by an external circuit) the bootloader will force menu mode instead of jumping to the application.
